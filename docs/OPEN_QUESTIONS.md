| Repeated “no active assignment” occurrences      | **D133** — **at most one** notification per reminder schedule generation, enforced by the unique identity rather than by application care                                                                                                                                                                                                                                                                                                                                                              |
| Capability expiry with no durable transition     | **D133** — **not deferred, and now closed.** Lazy expiry would never fire the ratified event, so A8.5d added a narrow database-backed sweep that transitions the capability, appends the audit event, and creates the intent in one idempotent transaction, and A8.5e wired it into the Owner notification worker's capture phase behind `ENABLE_OWNER_EVENT_CAPTURE`. The flag is unset everywhere and no cron job invokes the endpoint, so expiry is still observed only on the Recipient path today |
| Owner notification destination                   | **D134** — the organization's connected Gmail address on `CommunicationAccount`, resolved **at delivery time** and never persisted on the intent row. No Owner email column, no notification-address column, no destination environment variable, no Task- or Recipient-derived destination                                                                                                                                                                                                            |
| Whether D130 forbids links in Owner mail         | **D134** — **no.** D130 governs Recipient reminder emails and their capability bearer secret. An Owner authenticates with a session, so an authenticated Owner-surface link is not a credential. Token, `/c/` path, excerpt, and Recipient free-text prohibitions still apply from D109 and D114                                                                                                                                                                                                       |
| Whether D129 and D106 govern Owner notifications | **D135** — **no.** Both govern a repeating Recipient series. An Owner notification is one-shot: three total attempts on retryable failure, ambiguous terminal on first occurrence, no ceiling and no ambiguity-run stop                                                                                                                                                                                                                                                                                |
| Notification capture versus delivery gating      | **D135** — two independent exact-string `true` flags, both unset everywhere (**`F0`**). `ENABLE_OWNER_EVENT_CAPTURE` is evaluated **before** any mutation transaction opens — required when the decision was locked because A8 migrations were then unapplied, and still required so a disabled path issues no statement against the tables. Tables and capture code are now in Production (`D3`); first enablement is [Gate 6](DEPLOYMENT.md#gate-6--first-controlled-production-enablement-a87c-capture--f0--f1). `ENABLE_OWNER_EVENT_DELIVERY` gates the worker |
| Backlog flush when delivery is enabled           | **D135** — a **24-hour** staleness horizon: an older intent is terminalized as suppressed with a truthful reason and no provider call, so enablement order cannot produce a burst of stale mail                                                                                                                                                                                                                                                                                                        |
| Gmail self-ingestion of Owner notifications      | **D136** — a narrow `X-Rocket-Generated` marker from the controlled MIME builder, excluded at ingest. Excluding all `SENT` mail, or all mail whose sender equals the connected account, was rejected because both narrow D068 for genuine Owner mail                                                                                                                                                                                                                                                   |
